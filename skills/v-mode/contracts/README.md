# vstack 계약

vstack 관리자와 작업자가 지키는 계약이다. 관리자는 작업 명세에 필요한 계약 파일의 절대 경로를 넣는다. 작업자는 넘겨받은 파일만 읽는다.

| 파일 | 누가 읽나 | 내용 |
| --- | --- | --- |
| [priority.md](priority.md) | 관리자, 작업자 | 지시가 충돌할 때의 순위, 불변 규칙, 알려진 충돌과 답 |
| [worker-contract.md](worker-contract.md) | 작업자(모든 실행기) | 역할별 권한, 질문·막힘·완료 보고, 증거 쓰기 |
| [evidence.md](evidence.md) | 관리자, 작업자 | 증거 필드, 유효·통과의 정의, 수용 기준 집계, 최신성 |
| [merge-gate.md](merge-gate.md) | 관리자 | 병합 관문의 판정식과 진입점 |
| [archive.md](archive.md) | 관리자 | 증거 보관 절차, 중단 복구, 정리 조건 |
| [intake.md](intake.md) | 관리자 | 배정 전 입력 검사, 시범 부트스트랩 |
| [state-and-rollback.md](state-and-rollback.md) | 관리자 | 작업 파일 위치와 형식, 소유권, 새로 시작 |
| [reference-policy.md](reference-policy.md) | 작업자 | 원문 안의 출처 참조 가운데 실행하지 않는 것(스크립트가 만든다) |

레시피 형식은 [../recipes/FORMAT.md](../recipes/FORMAT.md)에 있다. 계약이 끝까지 판정되는지는 저장소의 `docs/contract-examples/`로 확인한다.

**버전**: 이 계약 묶음은 `vstack-contract@4`이다. `state.md`와 증거 manifest에 이 값을 적는다. 첫 시범을 시작하기 전까지는 `@1` 안에서 고치고, 시범을 시작한 뒤부터는 계약을 바꾸면 숫자를 올린다. 진행 중인 작업은 배정 때의 버전을 따른다.

- `@1`: 첫 시범(2026-11-08, `vstack-pilot-todo` 이슈 #1)에 쓴 버전.
- `@2`: 첫 시범의 관찰을 반영했다. manifest `session`은 세션 키(작업자는 터미널 핸들을 모른다), 과정 증거는 `process/`, 증거 안의 경로는 시도 폴더 기준 상대 경로, 시작 실패는 `취소` 뒤 새 시도 ID, 작업자가 읽을 범위에 레시피가 가리키는 스킬의 해당 절을 넣었다. 판정식(G1~G5)과 집계 규칙은 그대로다.
- `@3`: 두 번째 시범(실패 경로 주입)의 계약 질문을 반영했다. 결과 대상 확정에서 status가 비지 않으면 배정 전부터 있던 변경이어도 시도 전체(코드 검토 결론 포함) 무효. 작업 트리가 깨끗하지 않은 실행의 `verdict`는 `막힘`, 집계에서 유효하지 않은 기록은 `verdict`와 관계없이 증거 없음. 정지 확인 중 터미널이 해제되면 impl 인계. 띄우기 직전 기록에 파일 sha256. 명세 양식에 git 무시 줄. 판정식은 그대로다.
- `@4`: agent-orchestra 은퇴(2026-11-14, vstack 이슈 #22)를 반영했다. 소유권에서 기존 agent-orchestra 관리자와의 관계를 빼고, 되돌리기 두 길(새로 시작, 명시적 이행)을 vstack 안의 "새로 시작" 하나로 줄였다(state-and-rollback.md). 배정 전 입력 검사의 검증 명령 줄(intake.md)과 시작 실패가 아닌 복구(archive.md)가 실제로 있는 절을 가리키게 고쳤다. 판정식(G1~G5)과 작업자 의무는 그대로다.

**보장 범위**: 관문은 vstack 관리자가 실행하는 병합에만 보장된다. 첫 버전의 검증 대상은 Orca 실행 환경이다. Orca에서 정상 경로 시범(`docs/pilot-1.md`)과 실패 경로 주입 시범(`docs/pilot-2.md`: 시작 실패, 보관 대조 실패와 격리, 환경 막힘, dirty tree, rebase와 force-push 확인)을 했다. 관리자 재시작 뒤 이어받기는 구현 중에 끊긴 경우만 돌려 봤다(`docs/pilot-4.md`). 기능·리팩토링 레시피는 한 지휘에서 한 번씩 돌렸다(`docs/pilot-5.md`: 리팩토링은 `한 번에 전환`과 rebase 뒤 새 `P` 확인, 기능은 데이터 모양이 정해진 경우만). 같은 계열 검토, 보관 도중 끊긴 뒤의 중단 복구는 아직 돌려 보지 않았다. herdr는 검증 대상이 아니다.
