# 배정 전 입력 검사

관리자는 작업을 맡기기 전에 아래를 확인한다. 하나라도 빠지면 맡기지 않고 채운다. 사용자 결정이 필요한 항목이면 사용자에게 묻는다.

| 항목 | 확인 |
| --- | --- |
| 레시피 | 레시피 ID와 버전이 정해졌고, 그 레시피 파일이 있다 |
| 수용 기준 | 모두 `AC-<n>@<버전>` ID가 있고, 필수 여부가 정해졌고, 관찰 가능한 결과로 적혀 있다 |
| 검증 명령 | 필수 수용 기준마다 실행할 명령이나 절차가 있다. 없으면 맡기지 않는다. 검증 수단은 v-mode 고정 규칙 7과 "지휘" 2대로 지휘 전에 맡기기로 만든다([../SKILL.md](../SKILL.md), [../delegate.md](../delegate.md) "검증 수단이 없을 때") |
| seam | 테스트할 seam이 정해졌다. 버그 수정이면 재현 경로가 있다 |
| 전환 방식 | 리팩토링이면 "한 번에 전환" 또는 "expand–contract"가 적혀 있다 |
| 실행 조건 | 레시피의 실행 조건(예: bash, TTY, 실창 잠금)을 이 환경이 채운다 |
| 권한 | 역할, 증거 폴더, 검토 보고서 경로, scratch 경로, 건드리지 말 영역이 명세에 있다 |
| 준비·정리 | verify 스킬 경로 또는 명세에 준비·정리 절차가 있다 |
| 보관 준비 | [archive.md](archive.md) "준비"를 마쳤다 |

## 시범 부트스트랩

첫 시범은 v-mode 라우터와 `to-tickets` 양식 수정 전에 한다.

- 시범 티켓의 위 항목은 사용자와 관리자가 손으로 채운다.
- 관리자는 사용자가 `/vstack:orchestrate-issues`를 직접 실행해 시작한다. 이 스킬은 모델이 스스로 부르지 않게 막혀 있지만 사용자는 실행할 수 있다.
- `to-spec`·`to-tickets` 양식에 이 항목을 넣는 일은 시범 뒤에 한다.
