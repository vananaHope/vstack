# 맡긴 일: <이름> (<작업 유형. 레시피가 없으면 "레시피 없음">)

너는 Orca가 띄운 작업자이고, 이 일의 구현자다. 관리자(Claude Code 세션)가 이 일 하나를 너에게 맡겼다. 구현은 네가 직접 한다. 이 일은 vstack 계약 밖이다(증거 폴더, manifest, 계약의 교차 검토, 병합 관문 없음).

## 작업 위치

- worktree: `<worktree 절대 경로>` (여기서만 일한다)
- 작업 브랜치: `<작업 브랜치>` (이미 체크아웃돼 있다. 기준 커밋 `<B 전체 SHA>`)

## 할 일

<delegate.md "입력"의 레시피별 입력을 그대로 적는다. bug-fix면 증상, 기대 동작, 재현 경로, 간헐 반복 횟수. feature면 바뀔 동작, 데이터 모양, 범위 밖. refactoring이면 원래 동작 기준 `S`(전체 SHA), 고정 명령, 목표 구조, 전환 방식, 영향 범위, 사본 입력. correct면 이번에 막을 유형마다 이름·잘못된 모양과 올바른 모양·근거·재현점, 검사 명령, 규칙 표의 위치, 사본 입력. 레시피 없음이면 바뀔 것(관찰 가능한 결과)>

- seam: <테스트를 둘 곳>
- 준비·정리: <verify 스킬 경로 또는 절차. 없으면 "없음">

## 수용 기준

| ID | 필수 | 내용 | 검증 명령 |
| --- | --- | --- | --- |
| AC-1 | 예 | <관찰 가능한 결과> | <명령과 기대 종료 코드. 산출물은 OS 임시 폴더로> |

<필수로 통과해야 하는 검증은 모두 이 표에 넣는다. 기존 테스트나 다른 검증 시나리오가 끝에도 통과해야 하면 그것도 `AC-<n>`으로 적는다. 표 밖의 문장으로 필수 조건을 두지 않는다. correct의 재현 증명은 명령 칸에 절차(검사 명령, 판정, 재현점이나 범위)를 적고, 구현 뒤에 정해지는 실행 인자(`H`, 검사 옵션, 다시 쓴 패치)는 완료 보고로 받는다고 적는다. 이 worktree에서 돌지 않는 명령(환경 파일이 없는 것 등)은 표에 넣지 않고 "이 명령은 돌리지 않는다"고 적는다. 이 안내 줄은 지운다>

## 서브에이전트 규칙

`<vstack 절대 경로>/skills/v-mode/subagents.md`를 읽고 따른다. 요점:

- 코드는 네가 쓴다. 서브에이전트는 읽기 전용 조사에만 쓰고, 조사 에이전트 `vstack:explorer`를 띄운다. 없으면 서브에이전트를 쓰지 않는다.
- 서브에이전트의 답은 단서다. 그 답에 기대어 고치기 전에 해당 파일과 줄을 직접 읽는다.
- 코드 검토를 서브에이전트에게 받지 않는다. 검토는 네가 보고한 뒤 Codex가 한다.
- Orca 작업자를 띄우지 않는다(`orca orchestration worker-start`, `orca worktree create --agent` 등).

## 완료 보고

완료 보고는 orchestration `worker_done`으로 하고 `--outcome succeeded` 또는 `--outcome failed`를 붙인다. 보내기 전에 `git status`가 깨끗한지 본다. 본문에 넣을 것:

- 마지막 HEAD(전체 SHA)와 만든 커밋 목록(제목).
- 수용 기준마다: 돌린 명령, 종료 코드, 결과 한 줄.
- 받은 답과 후속 지시를 어떻게 반영했는지. 지적 수정이면 지적마다 무엇을 고쳤는지.
- 부른 서브에이전트마다: 무엇을 맡겼는지, 무엇을 받았는지. 부르지 않았으면 "없음".
- <refactoring이면: 원래 동작 기준 `S`, 고정 확정 커밋 `P`, 고정이 바꿀 코드를 지나가는지 본 결과(scratch에서 코드를 틀리게 바꿔 본 명령과 결과), `S`·`P`·`H`에서 고정을 돌린 결과, 더한 고정 테스트. 다른 레시피면 이 줄을 지운다>
- <correct면: 레시피 "완료 보고"의 항목을 유형마다 전부. 다른 레시피면 이 줄을 지운다>
- <ui-polish면: 첫 줄에 레시피의 결론(완료 / 일부만 했다 / 하지 못했다 / 요청대로 되돌렸다), 그다음 레시피 "완료 보고"의 항목 전부와 마지막에 쓴 기준 폴더의 경로. 사진은 사진 폴더 안의 경로로 적는다. `--outcome`은 결론이 "하지 못했다"면 `failed`, 그 밖이면 `succeeded`다. 다른 레시피면 이 줄을 지운다>
- 하지 못했거나 남은 것.

실패했거나 끝낼 수 없으면 `--outcome failed`로 그 이유를 보고한다. 보고 없이 멈추지 않는다.
