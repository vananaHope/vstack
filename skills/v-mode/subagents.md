# 서브에이전트

한 세션 갈래에서 Claude가 서브에이전트를 쓸 때의 규칙이다. 맡기기 구현 명세([delegate-spec.md](delegate-spec.md) "서브에이전트 규칙")와 v-mode "한 세션"이 이 파일을 가리킨다.

이 파일은 `<vstack>/skills/v-mode/subagents.md`다.

## 누구에게 적용하는가

- 한 세션 갈래에서 일하는 Claude: 맡긴 구현 작업자, 이 대화가 직접 할 때의 이 대화, 명세를 준비하는 관리자.
- 적용하지 않는 곳: 지휘의 계약 작업자(서브에이전트를 띄우지 않는다, [contracts/worker-contract.md](contracts/worker-contract.md)), 맡기기의 Codex 검토자.
- 사용자가 실행한 스킬(예: mattpocock-skills의 코드 검토 스킬)이 자기 서브에이전트를 정하면 그 스킬을 따른다. 맡긴 구현 작업자가 이 줄을 근거로 아래 제한을 스스로 풀지는 않는다.

## 무엇을 쓰는가

vstack 플러그인의 조사 에이전트 `vstack:explorer`를 띄운다. 정의([agents/explorer.md](../../agents/explorer.md))가 모델(`sonnet`)과 도구(읽기·검색 셋, 셸 없음)를 정하고, 에이전트가 지킬 규칙(읽기 전용, 판단하지 않음, 사실마다 파일과 줄)도 거기 있다. 부를 때 모델이나 종류를 따로 적지 않는다. 읽기 전용 조사에만 쓴다.

`vstack:explorer`가 목록에 없으면(플러그인이 이 버전보다 오래됨) 서브에이전트를 쓰지 않고 직접 찾아 읽는다. 다른 종류로 대신 띄우지 않는다.

## 언제 쓰는가

- **쓴다**: 여러 파일을 넓게 훑어야 할 때. 서로 상관없는 조사 여러 개를 동시에 돌릴 때. 긴 출력(로그, 큰 파일)을 읽고 요약만 필요할 때.
- **쓰지 않는다**: 어디를 볼지 이미 알 때. 도구 호출 몇 번이면 끝날 때.
- 두 쪽에 다 걸리면(볼 파일은 알지만 아주 긴 로그) 직접 찾아 읽는 것으로 되는지를 먼저 본다.

## 맡기지 않는 일

- 코드 쓰기와 커밋.
- 수용 기준 실행. 부른 쪽이 직접 돌린다.
- 원인과 설계의 판단. 서브에이전트는 자료를 모으고, 판단은 부른 쪽이 한다.
- 코드 검토. 맡기기에서는 Codex 검토자가 한다. 같은 계열(Claude)의 검토는 교차 검토가 아니다.

## 요청문

서브에이전트는 이 대화를 모른다. 에이전트가 지킬 규칙은 정의에 있으므로, 요청문에는 이 일에 대한 것을 적는다.

- 사용자의 목표(이 조사가 무엇을 위한 것인지).
- 볼 곳. 파일 내용을 붙여넣지 않고 경로로 준다.
- 이미 배제한 것.
- 돌려받을 형식이 정의의 기본 형식과 다르면 그 형식.

## 답을 다루는 법

- **답은 단서다.** 서브에이전트의 일은 부른 쪽이 책임진다. 그 답에 기대어 코드를 고치거나 사실을 주장하기 전에, 해당 파일과 줄을 직접 다시 읽는다. 받은 말을 그대로 옮기지 않는다.
- **이어 쓰지 않는다.** 후속 조사는 앞선 서브에이전트에게 덧붙이지 않고, 범위를 모아 새 서브에이전트에게 준다.

## 한도와 경계

- 서로 독립인 조사만 함께 띄운다. 한 번에 셋까지다.
- 맡긴 구현 작업자와 서브에이전트는 Orca 작업자를 띄우지 않는다. 관리자는 [delegate.md](delegate.md)가 정한 구현 작업자와 검토자만 띄운다.
- 완료 보고에 서브에이전트마다 무엇을 맡겼고 무엇을 받았는지 적는다.
