# 레시피 형식

레시피는 한 작업을 어떻게 하는지 적은 독립 문서다. Claude·Codex·OpenCode 작업자가 절대 경로로 받아 읽는다. 지휘(작업자 띄우기, 병합)는 레시피에 넣지 않는다.

## 틀

```markdown
# <레시피 이름>

id: <id> · version: <n> · contract: vstack-contract@<n>

## 언제
<이 레시피를 고르는 요청> / 쓰지 않을 때: <다른 레시피로 가는 경우>

## 입력
티켓·명세에서 받는 것. 관리자의 배정 전 입력 검사(`<vstack>/skills/v-mode/contracts/intake.md`)가 이 목록을 본다.
- 수용 기준(AC-<n>@<버전>, 필수 여부)
- <레시피별 항목: 재현 경로, seam, 전환 방식 …>

## 실행 조건
<필요한 셸·도구·잠금. 예: bash(Windows는 Git Bash), TTY 없음 가정>

## 단계
1. <도구 중립 동사로 쓴 단계. 다른 스킬은 경로로: "`<vstack>/skills/tdd/SKILL.md`를 읽고 그 순서를 따른다">
2. ...
역할에 따라 다른 단계는 `구현자:` / `검토자:`로 시작한다.

## 레시피 예외
`<vstack>/skills/v-mode/contracts/priority.md` "알려진 충돌과 답" 가운데 이 레시피에 해당하는 것.

## 후보 원칙
| 원칙 | 적용 조건 |
| --- | --- |
| `<vstack>/skills/principle-<이름>/SKILL.md` | <언제> |

## 완료 증거
| 수용 기준 | 캡처할 것 | 통과 조건 |
| --- | --- | --- |
| AC-1 | <터미널 기록, 스크린샷 …> | <관찰 가능한 결과> |
필드와 판정은 `<vstack>/skills/v-mode/contracts/evidence.md`를 따른다.

## 완료 보고
`<vstack>/skills/v-mode/contracts/worker-contract.md` "완료 보고" 항목 + 이 레시피만의 항목.
```

## 작성 규칙

- 단계는 도구 이름이 아니라 동사로 쓴다. "Skill 도구로 X를 불러라" 대신 "`<경로>`를 읽고 따른다".
- 사람에게 묻는 단계를 넣지 않는다. 필요하면 "관리자에게 묻고 `막힘`으로 기다린다".
- 하위 에이전트를 띄우는 단계를 넣지 않는다.
- `<vstack>`은 vstack 플러그인 루트다. 관리자가 명세에 넣을 때 절대 경로로 바꾼다. 티켓에는 레시피 ID만 적는다.
- 레시피를 바꾸면 `version`을 올린다. 진행 중인 작업은 배정 때의 버전을 따른다.
- 레시피가 가리키는 모든 경로는 실제 파일이어야 한다(1단계의 링크 검사 대상).
