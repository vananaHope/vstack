# 레시피 형식

레시피는 한 작업을 어떻게 하는지 적은 독립 문서다. Claude·Codex·OpenCode 작업자가 절대 경로로 받아 읽는다. 지휘(작업자 띄우기, 병합)는 레시피에 넣지 않는다.

## 틀

```markdown
# <레시피 이름>

id: <id> · version: <n> · contract: vstack-contract@<n>

## 언제
<이 레시피를 고르는 요청> / 쓰지 않을 때: <다른 레시피로 가는 경우>

## 입력
티켓·명세에서 받는 것. 관리자의 배정 전 입력 검사(`<vstack>/skills/v-mode/contracts/intake.md`)가 이 목록을 본다.
- 수용 기준(AC-<n>@<버전>, 필수 여부)
- <레시피별 항목: 재현 경로, seam, 전환 방식 …>

## 실행 조건
<필요한 셸·도구·잠금. 예: bash(Windows는 Git Bash), TTY 없음 가정>

## 단계
1. <도구 중립 동사로 쓴 단계. 다른 스킬은 경로로: "`<vstack>/skills/tdd/SKILL.md`를 읽고 그 순서를 따른다">
2. ...
역할에 따라 다른 단계는 `구현자:` / `검토자:`로 시작한다.

## 레시피 예외
`<vstack>/skills/v-mode/contracts/priority.md` "알려진 충돌과 답" 가운데 이 레시피에 해당하는 것.

## 후보 원칙
| 원칙 | 적용 조건 |
| --- | --- |
| `<vstack>/skills/principle-<이름>/SKILL.md` | <언제> |

## 완료 증거
| 수용 기준 | 캡처할 것 | 통과 조건 |
| --- | --- | --- |
| AC-1 | <터미널 기록, 스크린샷 …> | <관찰 가능한 결과> |
필드와 판정은 `<vstack>/skills/v-mode/contracts/evidence.md`를 따른다.

## 완료 보고
`<vstack>/skills/v-mode/contracts/worker-contract.md` "완료 보고" 항목 + 이 레시피만의 항목.
```

## 작성 규칙

- 단계는 특정 런타임의 도구 이름이 아니라 동사로 쓴다. 스킬을 이름으로 부르게 하지 말고 "`<경로>`를 읽고 따른다"로 쓴다.
- 사람에게 묻는 단계를 넣지 않는다. 필요하면 "관리자에게 묻고 `막힘`으로 기다린다".
- 하위 에이전트를 띄우는 단계를 넣지 않는다.
- `<vstack>`은 vstack 플러그인 루트다. 관리자가 명세에 넣을 때 절대 경로로 바꾼다. 티켓에는 레시피 ID만 적는다.
- 레시피를 바꾸면 `version`을 올린다. 진행 중인 작업은 배정 때의 버전을 따른다.
- 한 세션 갈래에서만 쓰는 레시피(지금은 `ui-polish`)는 머리말에 그렇게 적는다. 지휘에 연결하기 전까지는 검토자 절차와 증거 만들기 단계를 두지 않아도 된다. 그런 레시피에서 구현자는 v-mode를 돌리는 대화이고 관리자는 사용자이므로, 위 "사람에게 묻는 단계를 넣지 않는다" 대신 "사용자에게 묻는다"고 쓴다. `contract` 줄은 지휘에 연결할 때 맞출 계약 버전이다.

## 실행 경로 표기

레시피, 계약, `adapted`·`extracted`로 가져온 파일에서 작업자가 따라가야 하는 vstack 안의 파일은 두 형태로만 쓴다. `scripts/check-links.mjs`가 이 형태를 검사한다.

| 형태 | 기준 | 예 |
| --- | --- | --- |
| Markdown 링크 | 그 파일이 있는 폴더 | `[HITL 스크립트](scripts/hitl-loop.template.sh)` |
| `<vstack>/` 경로(인라인 코드) | 플러그인 루트 | `` `<vstack>/skills/tdd/SKILL.md` `` |

- vstack 안을 가리키는 경로를 그냥 인라인 코드(`` `scripts/x.sh` ``)로 쓰면 검사가 실패한다(`NONSTANDARD`). 원본이 그렇게 써도 가져올 때 위 형태로 바꾼다.
- 작업 대상 저장소의 경로(`.local/vstack/...`, `docs/agents/orchestration.md` 등)는 vstack 파일이 아니므로 인라인 코드로 쓴다.
- 스킬을 이름으로 가리키는 표현(`` `이름` 스킬``, `` `/이름` ``)은 vstack에 있는 스킬일 때만 쓸 수 있다(`SKILL` 검사). 특정 런타임의 스킬 도구로 부르라는 문장은 쓸 수 없다(`TOOL` 검사).
