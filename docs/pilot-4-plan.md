# 네 번째 시범 계획: 관리자 재시작 뒤 이어받기

지금까지 세 시범은 관리자 세션 하나가 처음부터 끝까지 지휘했다. 라우터 고르기 0은 "관리자가 바뀌었거나 다시 시작했으면 orchestrate-issues가 `state.md`와 보관된 증거로 이어 간다"고 하지만, 이 경로는 한 번도 돌려 보지 않았다. 이번에는 지휘 도중 관리자 세션을 실제로 닫고, 새 세션이 이어받게 한다. 같이 0.5.0 라우터 반영분(시범 3 D1·D8) 가운데 자연스럽게 나오는 것을 본다.

- 저장소: `vananaHope/vstack-pilot-todo` · 실행 환경: Orca · 플러그인 vstack 0.5.0 · 계약 `vstack-contract@3` · 레시피 `bug-fix@4`
- 실행기: Codex(구현), Claude(검토). OpenCode는 쓰지 않는다(계정 막힘). 명세 새 눈 점검은 서브에이전트.
- 병합 방식: `지시`. 병합·force-push는 이름을 적은 사용자 승인으로만 한다(고정 규칙 5).
- 관리자 세션: **A**(지금 세션, 배정까지), **B**(새 Claude Code 세션, 이어받기). 선택 단계에서 **C**.

## 준비(시범 저장소 `main`, 시범 준비 예외)

시범 3 D3의 "지휘 전 준비 변경"이다. 방법은 직접 커밋(시범 준비 예외, `pilot-2-plan.md` "준비"와 같은 확인: 원격·경로, 준비 전 SHA 기록)으로 하고, 이 계획 승인으로 확인받은 것으로 본다. **준비 커밋 메시지는 중립적으로 쓴다**(시범 3 D7).

1. `scripts/verify.mjs`에 시나리오 `empty-title`을 더한다: 제목이 `""`와 `"   "`인 v2 파일을 쓰고 새 프로세스로 `list`(텍스트)를 돌려, 두 줄이 `(제목 없음)`인지 본다. 지금 `main`에서 실패(red)하고, 로컬 브랜치 `fix/empty-title-list`의 수정을 얹으면 통과(green)하는지 관리자가 확인한다. verify 스킬 `features/`에 문서를 더한다.
2. 이슈를 만든다(라벨 `ready-for-agent`, 본문에 증상·기대 동작·완료 기준 체크리스트·vstack 절). 버그는 `main`에 이미 있는 것(`formatList`가 `??`로 빈 문자열을 거르지 못함, 시범 3 요청 2에서 심고 로컬에서만 고친 것)을 쓴다. 로컬 브랜치 `fix/empty-title-list`는 지우지 않고, 작업자에게 보이지 않게 시범 동안 그대로 둔다(push하지 않았으므로 worktree에 없다).
   - vstack 절: `bug-fix@4`, `AC-1@1` 증상 해소(`node scripts/verify.mjs empty-title --out <증거 폴더>/ac-1`), `AC-2@1` 회귀 테스트(`node --test test/`), seam `formatList`, 결정적, 건드리지 말 영역 `addTodo`·`markDone`·`src/store.mjs`·`scripts/verify.mjs`.

## 끊는 지점과 기대 동작

| # | 끊는 지점 | 끊은 것의 확인 | 기대 동작(근거) |
| --- | --- | --- | --- |
| R1 | A가 구현자(Codex)를 띄우고 **제출 확인까지 한 직후**. `state.md`(구현 중, 시도 `배정됨`, dispatch·세션 기록)를 쓴 뒤 A는 더 아무것도 하지 않고, 사용자가 A 세션을 닫는다. 구현자는 A가 없는 동안 끝나 `worker_done`을 보낸다 | 사용자가 A를 닫은 시각이 구현자 `worker_done` 시각보다 앞선다(`worker-show`·`inbox`의 시각으로 B가 확인) | B에서 사용자가 `/vstack:v-mode`로 이어 가라고 하면: 고르기 0 → "관리자가 바뀌었거나 다시 시작" → **이어 가기 전에 "이 경로는 시범으로 돌려 보지 않았다"를 사용자에게 알린다**(라우터). orchestrate-issues "가장 먼저: 설정 확인" → 1단계 "지휘를 처음 시작할 때 `state.md`를 훑어 이어 갈 작업을 알린다" → archive.md "중단 복구"로 시도마다 상태 확인. Run은 `run-use --id <run>`으로 이어받는다(Orca). 구현자 보고는 `inbox`나 `worker-show`로 찾는다. 찾으면 "완료 보고를 받으면"(보관 → 결과 대상 확정) → 4단계 교차 검토. 보고를 찾지 못하면 그 시도를 "보고 없이 멈춤"으로 보고 vstack.md "복구"(정지 확인 → 증거 없음 정산 → 구현이 끝났으면 재검증)로 간다. 어느 쪽이든 추측으로 정산하지 않는다 |
| R2(선택) | B가 검토자의 `worker_done`을 받아 보관 1~3(복사·대조·승격)을 한 뒤, 4(포인터) 전에 멈추고 사용자가 B를 닫는다 | 보관 폴더 `evidence/<rev 시도 ID>/`가 있고, `state.md`의 그 시도 줄에 보관 경로·manifest 해시가 없다 | C가 이어받으면: archive.md "중단 복구" "승격 뒤, 포인터 전" 행 → 보관 폴더를 manifest `files`와 대조 → 맞으면 4(포인터)부터 → 5(원본 정리) → 5단계 판정. 다시 복사하거나 덮지 않는다(archive.md "이미 보관됨 이상인 시도는 다시 복사하지 않는다"는 포인터 뒤 기준이므로, 여기서는 대조가 기준이다) |

R2는 R1 결과를 보고 사용자가 할지 정한다. R2를 하지 않으면 B가 끝까지(지시 대기) 간다.

## 같이 볼 것(0.5.0 반영분)

- D8: B가 PR·병합 승인을 구할 때 "병합"을 질문에 이름으로 적는가. 짧은 승인으로 병합하지 않는가.
- D1(선택): 지휘 중 사용자가 작은 수정을 요청하면 `user-request-<k>.md`를 남기고 `fixes.md`로 맡기는가. R1에서 B가 검토자를 띄운 뒤 사용자가 요청한다. 수정 경로까지 돌리면 재검증·새 `review`가 붙어 시간이 늘어나므로, 요청 여부는 사용자가 정한다.

## 시범으로 답할 질문

- Q1: A가 닫힌 뒤 도착한 구현자 `worker_done`을 B가 볼 수 있는가(`inbox --terminal run:<run>`, `worker-show`). B가 `run-use`로 Run을 이어받으면 그 뒤의 작업자 보고가 B를 깨우는가.
- Q2: A가 닫힐 때 Orca가 A가 띄운 작업자를 어떻게 다루는가(작업자는 계속 도는가, `terminalState`).
- Q3: 계약 문서만으로 B가 이어 갈 수 있는가. 막히는 곳(예: 보고는 있는데 B가 받은 적이 없는 `worker_done`을 "완료 보고를 받으면"의 입력으로 써도 되는가)은 계약 질문으로 적는다.

## 관찰자 역할

B와 C는 이어받는 관리자이면서 시범 기록자다. 이어받기를 오염시키지 않으려고:

- A는 B에게 이 작업의 상태를 따로 넘기지 않는다. B가 쓰는 것은 `state.md`·작업 파일·보관 증거·Orca 기록뿐이다.
- A는 `.local/handoff-pilot-4.md`에 관찰자 지시만 남긴다: "사용자가 이어 가라고 하기 전에는 시범 저장소 작업 파일과 이 계획을 읽지 않는다. 이어받기를 끝까지(또는 R2 끊는 지점까지) 한 뒤 이 계획을 읽고 `docs/pilot-4.md`를 쓴다."
- 그래도 B가 이 계획의 존재를 안다는 것은 한계로 기록한다.

## 순서

1. A: 준비 1·2. 사용자에게 준비 결과를 보이고 확인받는다.
2. A: 사용자가 `/vstack:v-mode <이슈> 진행해`로 지휘를 시작한다. 지휘 → 구현자 띄우기 → 제출 확인 → `state.md`. A는 관찰자 인계 파일을 쓰고 "지금 닫아 달라"고 알린다(R1).
3. 사용자: A 세션을 닫고, 새 Claude Code 세션 B를 연다. B에게 `.local/handoff-pilot-4.md`를 읽게 한다.
4. 사용자: B에서 `/vstack:v-mode vstack-pilot-todo <이슈> 이어 가` 같은 문장을 직접 입력한다.
5. B: 이어받기 → 보관 → 검토자 → (R2 또는 끝까지) → 지시 대기.
6. (R2를 하면) 사용자: B를 닫고 C를 연다. C에서 이어 가라고 한다.
7. 사용자 지시가 있으면 PR·병합(이름을 적은 승인).
8. 마지막 관리자가 `docs/pilot-4.md`를 쓴다: 끊는 지점마다 기대와 실제, Q1~Q3 답, 어긋난 곳, 원인(라우터·계약 문서 / Orca 동작 / 실행 실수), 고칠 것.

## 멈춤 기준

- B·C가 작업자 정지를 증명하지 못하면 아무것도 정산하지 않고 "정지 미확인"을 알린다(vstack.md "복구").
- 유효하지 않은 증거로 병합 관문을 통과시키려 하면 멈춘다. 이어받기를 성공시키려고 관문을 건너뛰지 않는다.
- 이어받은 관리자가 계약에 답이 없는 상황을 만나면 추측하지 않고 사용자에게 묻고, 그 상황을 Q3로 기록한다.
- 사용자 확인이 필요한 곳: 준비 결과, A를 닫는 시점, R2 여부, D1 요청 여부, PR, 병합.
