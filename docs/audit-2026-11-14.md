# vstack 전체 검수(2026-11-14)

대상: `main` `582d21d`(0.14.0, "관리자는 관리만" 병합 뒤). 이슈 [#20](https://github.com/vananaHope/vstack/issues/20).

## 어떻게 했나

- 사실 모으기: 0.14.0이 실린 새 Claude 세션을 읽기·검색 도구만 주고 띄워, 영역 여섯(라우터와 맡기기, 지휘와 설정·한도, 원칙, mattpocock 사본, 그 밖의 스킬, 문서)마다 조사 에이전트 `vstack:explorer`를 하나씩 띄웠다. 사실 목록 원문은 관리자의 임시 폴더에 있다(이 문서에 필요한 것은 아래에 옮겼다).
- 판단: 관리자(이 세션)가 아래 항목의 근거를 직접 다시 읽어 확인한 뒤 분류했다. 조사 결과를 그대로 옮기지 않았다.
- 출처 대조: `node scripts/check-links.mjs --source pstack=<pstack 저장소> --source mattpocock-skills=<1.3.1 설치본> --source agent-orchestra=<로컬 클론 c62be33>`. **306 경로, 실패 0건.** 지금까지는 출처 폴더를 주지 않아 closure 검사가 늘 건너뛰어졌다(`CLOSURE` 8건). pstack은 고정 커밋이 아니라 최신 main(`24621db`, 0.15.36과 줄바꿈만 다름)으로 대조했다.
- 분류: **남김**(그대로 둔다), **고침**(문장이나 기록을 바로잡는다), **뺌**(지운다), **결정 필요**(사용자가 정한다. 추천을 적었다).

## 한 장 요약: vstack이 지금 하는 일

- `/vstack:v-mode`가 요청을 **바로 / 맡기기 / 지휘**로 보낸다. 관리자(그 대화)는 바로 갈래 말고는 제품 코드를 쓰지 않는다.
- **맡기기**: 한 단위의 일을 Orca로 띄운 Claude 구현자가 새 worktree에서 구현하고, Codex 검토자가 검토하고, 관리자가 수용 기준을 다시 돌려 확인한다. 레시피 넷(`bug-fix@5`, `feature@2`, `refactoring@3`, `ui-polish@3`)이나 레시피 없이 수용 기준만으로. 계약 밖.
- **지휘**: 정렬(mattpocock) → 티켓의 vstack 절 → 작업자 배정 → 다른 계열의 교차 검토 → 증거 보관 → 병합 관문. 계약 `vstack-contract@3` 안. agent-orchestra에서 옮겨 와 고쳤다.
- 받침: pstack 원칙 24개(원문 그대로), 고쳐 쓴 사본(`tdd`, `diagnosing-bugs`, `create-verification-skill`, `blast-radius`), 조사 에이전트 `vstack:explorer`, 링크·출처 검사.
