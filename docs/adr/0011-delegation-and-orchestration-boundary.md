# 맡기기와 지휘는 티켓과 계약이 필요한가로 나눈다

둘 다 작업자를 띄우고 다른 계열이 검토한다. 맡기기는 대화에서 받은 한 단위의 일이고, 계약(증거 폴더, manifest, 시도 정산, 병합 관문)이 없으며, 반영 방법은 사용자가 정한다. 지휘는 이슈 저장소의 티켓이고, 여러 단위를 순서와 의존대로 진행하며, 계약을 지킨다. 위험이 크거나(인증, 데이터 변경, 공용 API, 보안) 여러 단위로 나눠야 하면 크기가 작아도 지휘다. 경계를 작업자 수로 정하지 않는다.

한 저장소의 관리자는 하나이고, 지휘와 맡기기를 같은 저장소에서 함께 진행하지 않는다. 맡기기끼리는 서로 쓰는 곳과 검증 자원이 겹치지 않으면 함께 진행할 수 있다(2026-11-13 사용자 결정, 문서 반영 전).

**Considered Options**: 둘을 하나로 합치고 계약을 선택 사항으로 두는 길은 버렸다. 계약이 붙었는지가 갈래 이름으로 드러나지 않으면, 증거 없이 병합된 결과와 관문을 통과한 결과를 구분할 수 없다.
