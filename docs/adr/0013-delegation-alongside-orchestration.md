# 지휘와 맡기기는 쓰는 곳과 검증 자원이 겹치지 않으면 함께 진행한다

[ADR 0011](0011-delegation-and-orchestration-boundary.md)은 "지휘와 맡기기를 같은 저장소에서 함께 진행하지 않는다"고 정했다. 이 결정은 그 문장을 바꾼다. 같은 메인 저장소에서 진행 중인 지휘 작업과 맡기기는 서로 쓰는 곳(예정 쓰기 영역)과 검증 자원이 겹치지 않으면 함께 진행한다. 겹치는 이슈나 맡기기만 뒤로 미룬다. 맡기기끼리 쓰던 기준을 지휘와 맡기기 사이에도 쓴다(2026-11-24 사용자 결정).

ADR 0011의 나머지는 그대로다. 한 저장소의 관리자는 하나이고, 함께 진행하는 지휘 작업과 맡기기는 한 관리자 세션이 같은 Run으로 다룬다. 기록(`.local/vstack/`, `.local/vstack-delegate/`), worktree, 작업자는 원래 나뉘어 있었다. 맡기기의 반영과 지휘의 병합은 한 번에 하나만 하고, 기준 브랜치가 움직이면 양쪽은 이미 있는 규칙(맡기기의 기준 비교, 병합 관문의 rebase 행)으로 따라간다. 그래서 계약과 병합 관문은 바뀌지 않는다(`vstack-contract@5` 그대로).

두 가지를 더 막는다. 첫째, 지휘가 진행 중인 동안 맡기기를 지휘의 기준 브랜치(`main`)에 로컬 병합으로 반영하지 않는다. 지휘는 새 worktree와 rebase를 로컬 `main`에서 하므로, push하지 않은 맡기기 병합이 다음 지휘 작업의 PR에 실려 나가고 병합 관문은 그것을 보지 않는다. 반영은 PR이나 그대로 둠으로 하고, 지휘가 새 작업을 시작할 때 로컬 `main`에 `origin/main`에 없는 커밋이 없는지 본다. 둘째, Run이 같다는 것만으로 이 세션이 관리자라고 보지 않는다. Run을 함께 쓰므로 한쪽만 이어받아도 다른 쪽과 Run이 같아진다. 다른 쪽 메시지를 처리하기 전에 그쪽 이어받기(지휘는 `vstack.md` "관리자 재시작", 맡기기는 `delegate.md` "관리자가 다시 시작했을 때")를 먼저 한다.

겹침은 지휘를 시작할 때 한 번에 선언하지 않고 지휘 작업마다 본다. 지휘는 진행하면서 이슈를 고르므로 시작할 때 범위를 다 알 수 없다. 대신 이미 있던 "새 작업 시작 조건"(진행 중인 작업과 같은 파일 영역을 건드리지 않는다)에 맡기기를 더하고, 지휘 작업은 `task.md`의 Target과 "검증 자원" 줄로 예정 쓰기 영역과 검증 자원을 적는다. 범위가 넓어질 때(지적 수정, 리뷰 반영, 맡기기의 후속 요구 등)에도 다시 본다.

**바뀜(2026-11-25)**: 둘째 문단의 "한 저장소의 관리자는 하나"와 Considered Options의 "두 관리자 세션이 같은 저장소를 나눠 맡는 길은 열지 않았다"는 [ADR 0014](0014-one-manager-per-record.md)가 바꿨다. 관리자는 기록마다 하나이고, 다른 관리자의 기록은 겹침 판정에만 읽는다. 겹침 기준, 로컬 병합 금지, 같은 세션 안에서 Run 하나는 그대로다.

**Considered Options**: 아무것도 막지 않는 길은 버렸다. 두 쪽이 같은 파일을 쓰면 반영 때 충돌을 작업자에게 되돌려야 하고, 포트·DB 같은 검증 자원을 함께 쓰면 한쪽 검증 결과가 다른 쪽 때문에 틀린다. 그대로 두는 길도 버렸다. 맡기기끼리는 같은 기준으로 함께 진행하는데 지휘와 맡기기 사이에만 무조건 금지를 두는 것은 지나치다. 지휘를 시작할 때 다룰 범위를 한 번에 선언하는 길도 생각했지만, 범위가 넓어질 때 다시 봐야 하는 것은 같고 선언과 실제 작업이 어긋날 수 있어 작업마다 보는 쪽을 골랐다. 로컬 병합이 섞이는 문제는 지휘를 `origin/main` 기준으로 돌려서 막을 수도 있었다. 그 길은 Orca의 worktree 만들기와 rebase 명령, 병합 뒤 pull 절차를 함께 바꿔야 하고 아직 Orca에서 확인하지 않은 동작에 기댄다. 그래서 지휘 절차는 그대로 두고 맡기기 쪽 반영 방법을 좁히는 쪽을 골랐다. 두 관리자 세션이 같은 저장소를 나눠 맡는 길은 열지 않았다. Orca의 `run-use`가 Run 하나만 남기고, 메시지를 기록으로 나누는 일이 한 관리자를 전제한다.

**돌려 보지 않았다.** 지휘와 맡기기를 함께 진행한 시범은 아직 없다.
