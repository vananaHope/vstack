# omp를 쓰지 않는다

한때 omp를 두 자리에 넣었다: v-mode를 omp에서도 돌리는 길(2026-11-10), 한 세션 일을 omp 작업자 하나에게 맡기는 길(omp가 Claude로 구현하고 자기 안의 gpt 계열 서브에이전트로 검토). 2026-11-13에 둘 다 뺐다.

맡기기의 이점(쓴 쪽과 확인하는 쪽이 다르다, 관리자 대화가 가볍다, 새 worktree로 격리된다)은 omp가 아니라 작업자에서 나온다. omp 안의 검토는 관리자가 요약으로만 봤다. omp는 의존 도구를 하나 더 들였고, 2026-11-12에는 OS 보안 정책이 omp의 네이티브 모듈을 막아 하루 동안 맡기기를 못 썼다. Orca는 omp의 턴 시작을 관측하지 못했다. 그래서 구현은 Claude 작업자, 검토는 Codex 작업자로 바꿨다(0009).

**Considered Options**: omp를 지휘 작업자로 더하는 길(2026-11-12)도 버렸다. 교차 검토의 "구현자와 다른 계열"을 판정하려면 omp가 그때 어떤 모델로 도는지 관리자가 알아야 하는데, 모델은 omp 설정이 정했다. 잃은 것은 omp의 역할별 모델 설정과 한도가 떨어지면 다른 모델로 넘어가는 기능이다.
