# 지휘에서는 증거를 다시 쓰지 않는다

지휘의 계약은 병합 전에 구현자와 검토자가 같은 수용 기준을 각자 새 상태에서 돌린 증거를 요구한다. 대상(head나 base)이 바뀌면 두 역할이 필수 수용 기준을 모두 다시 돌린다. 패치가 같아 보여도(`patch_id`가 같아도) 예외를 두지 않는다. `patch_id`는 참고로만 적는다.

pstack의 `shipping` 플레이북은 일부 경우에 이전 검토를 다시 쓸 수 있게 한다. 그 예외는 "무엇이 같으면 같은가"의 판단을 관리자에게 맡긴다. 그 판단이 틀리면 검토되지 않은 코드가 병합된다. 재실행 비용을 더 내고 판단을 없앴다.
