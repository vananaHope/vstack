# 관리자는 제품 코드를 쓰지 않는다

사용자가 v-mode를 실행한 대화(관리자)는 갈래를 고르고, 일을 넘기고, 작업자의 질문에 답하고, 수용 기준을 다시 돌려 확인하고, 반영하고, 보고한다. 제품 코드를 쓰는 일, 검증 수단을 만드는 일, 충돌을 푸는 일은 작업자에게 맡긴다(2026-11-13·14 사용자 결정). 코드를 쓴 쪽이 자기 결과를 스스로 통과시키지 않게 하려는 것이다. 첫 `ui-polish` 실사용에서 어긋난 것 둘(비교 화면이 다른 채로 커밋, 판정 규칙을 결과를 본 뒤에 바꿈)이 그런 경우였다.

관리자가 바로 하는 수정은 제품이 실행하거나, 화면에 보이거나, 검증이 읽는 파일을 고치지 않는 것뿐이다. 문서, 코드 주석의 오타, vstack 자신의 스킬과 문서다. 그 밖은 모두 맡긴다. 동작이 바뀌는 수정은 한 줄이어도, 화면에 보이는 문구는 한 글자라도 맡기고, 동작을 보존하는 리팩토링·UI 다듬기·검증 수단 만들기도 맡긴다. 판단이 서지 않으면 맡긴다. 한 줄 버그 수정에도 몇 분이 더 들지만, 예외를 두면 경계가 다시 흐려진다.

**Considered Options**: 처음에는 "동작이 바뀌는가"를 경계로 정했다(2026-11-14 정렬). 그렇게 두면 동작을 보존하는 리팩토링과 UI 다듬기까지 관리자가 할 수 있게 읽혀서(Codex 검토 지적), 같은 날 지금의 좁은 정의로 바꿨다.

**Consequences**: 맡길 수 없으면(Orca가 아니다, 진행 중인 지휘가 있다, 준비가 안 된다) 관리자가 대신 하지 않고 멈춘다. 사용자가 "여기서 해"라고 명시하면 따르되 검토가 붙지 않는다는 것을 알린다.
