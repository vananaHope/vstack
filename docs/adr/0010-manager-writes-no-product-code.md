# 관리자는 제품 코드를 쓰지 않는다

사용자가 v-mode를 실행한 대화(관리자)는 갈래를 고르고, 일을 넘기고, 작업자의 질문에 답하고, 수용 기준을 다시 돌려 확인하고, 반영하고, 보고한다. 제품 코드를 쓰는 일, 검증 수단을 만드는 일, 충돌을 푸는 일은 작업자에게 맡긴다(2026-11-13·14 사용자 결정). 코드를 쓴 쪽이 자기 결과를 스스로 통과시키지 않게 하려는 것이다. 첫 `ui-polish` 실사용에서 어긋난 것 둘(비교 화면이 다른 채로 커밋, 판정 규칙을 결과를 본 뒤에 바꿈)이 그런 경우였다.

경계는 "동작이 바뀌는가"다. 오타, 문구, 주석, 문서처럼 동작이 바뀌지 않는 수정은 관리자가 바로 한다. 동작이 바뀌는 수정은 한 줄이어도 맡긴다. 한 줄 버그 수정에도 몇 분이 더 들지만, 예외를 두면 경계가 다시 흐려진다.

**Consequences**: 맡길 수 없으면(Orca가 아니다, 진행 중인 지휘가 있다, 준비가 안 된다) 관리자가 대신 하지 않고 멈춘다. 사용자가 "여기서 해"라고 명시하면 따르되 검토가 붙지 않는다는 것을 알린다.
