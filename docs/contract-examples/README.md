# 계약 예시

`skills/v-mode/contracts/`(`vstack-contract@5`)가 끝까지 판정되는지 확인하는 예시다. 계약만 보고 각 예시의 판정을 다시 낼 수 있어야 한다. 그러지 못하는 곳은 계약의 모호함이므로 계약을 고친다.

`@5`로 다시 판정했다(2026-11-15). 판정은 `@4` 때와 같다. 바뀐 것은 계약 버전·레시피 버전 문자열과, OpenCode 작업자가 나오던 01d·01f·02a를 Codex로 바꾼 것이다. 02a의 rebase는 원래 구현자의 계열(codex)이 하므로 검토자(claude)의 역할 자격이 그대로 성립한다.

`@4`로 다시 판정했다(2026-11-14). 판정은 `@3` 때와 같다. 바뀐 것은 계약 버전 문자열과 04f의 장면이다: 되돌리기 두 길 가운데 "명시적 이행"이 없어져 "새로 시작" 하나만 남았고, 다시 맡기는 곳이 기존 agent-orchestra 관리자가 아니라 vstack 지휘다. 04f에는 다시 맡기는 작업이 새 작업 이름(`issue-42-r2`)과 새 폴더를 쓰고 옛 기록을 그대로 두는 장면을 더했다(state-and-rollback.md "다시 맡길 때의 작업 이름").

| 예시 | 다루는 것 |
| --- | --- |
| [01-normal.md](01-normal.md) | 입력 검사 값, 정상 병합과 `MERGED` 확인, 최신 실패 증거, 수용 기준 통과 + 미해결 중요 지적, light 등급의 관리자 검토 건너뛰기, dirty tree, 사소 지적 수정 뒤 G1·G3 근거 |
| [02-base-change.md](02-base-change.md) | 지시 대기 중 기준 브랜치 이동, rebase 뒤 두 역할 재검증과 manifest, 테스트 약화, 같은 세션 검토 금지, 기준 브랜치 경쟁, "병합됐어"인데 열린 PR, rebase 병합 |
| [03-blocked.md](03-blocked.md) | 환경 원인 막힘과 `rerun-only` 재배정, 필수 수용 기준의 `해당 없음`, 제품 결정과 수용 기준 버전(H가 바뀌는 경우와 아닌 경우), 입력 검사의 seam, 맡은 시도가 결과를 잃음 |
| [04-archive-failure.md](04-archive-failure.md) | 보관 중단 지점 다섯 곳, `증거없음` 정산과 정지 확인·격리, 보관 손상에서 완료까지, 격리 원본 일부 삭제 뒤 재시작, 손상 이름 바꾸기 직후 재시작, 새로 시작(미병합 worktree 보존), impl 인계 |

공통 설정:

- 저장소: 할 일 앱(웹). 기준 브랜치 `main`. 병합 방식 `지시`, 병합 방법 `squash`(02f만 `rebase`).
- SHA는 읽기 쉽게 줄여 쓴다(`H1=1111aaa`). 실제 manifest에는 40자를 쓴다. 세션은 `term-*`로 줄여 쓴다.
- 실행 환경: Orca.
- 이 예시들은 문서 수준의 판정이다. 실제 앱·manifest·해시로 돌려 보는 것은 시범 단계(만드는 순서 4)의 일이다.
